# 010 - 清空边界与收发回归验收

## Parent PRD

`docs/requirements/REQ-0003-serial-receive-event-timestamp-log.md`（第 10、10.1、11、12、13、14、15.5、17 节；实施决策 5；测试决策 5-6；验收标准 5、9-10、17-18）

## What to build

完成清空操作的跨线程边界处理，并补齐 REQ-0003 的整体验收回归：

- 点击“清空”时清除当前显示、完整接收事件历史和时间戳历史，调用当前会话的 `reset_receive_session()`，重置分帧器的未完成尾部、超长丢弃状态和诊断队列。
- 会话锁内的代次切换是清空的唯一线性化点：原子丢弃点击时事件队列中尚未显示的旧 `ReceivedEvent`；reader 发布事件前验证代次仍有效。点击后新到达的数据使用新会话正常进入接收链路并显示、记录日志。
- 清空后切换显示时间戳、文本/HEX或编码不会复活旧事件；旧事件即使已经写入日志也不得被修改或删除。不能通过删除日志文件来实现清空。
- 发送区继续支持文本和 HEX：文本按当前编码发送，HEX 按输入解析发送；沿用现有单行输入和回车发送行为，文本模式不自动追加结束符，需要发送 `\r\n` 时在 HEX 模式显式输入 `0D 0A`；不生成 `ReceivedEvent`，不写 `RX` 日志。
- 使用 fake serial、fake 时间源、临时日志目录和 Qt offscreen 环境完成需求验收矩阵；测试应在按 `requirements.txt` 和 `requirements-dev.txt` 安装的干净环境中执行。真实串口端到端只作为 Windows 手工验收，不加入自动化依赖。
- 当前开发环境的 com0com 端口为 `COM17 <-> COM19`，默认手工串口验收使用该端口对和 `115200 / 8 / N / 1` 流程；端口号由 Windows/com0com 分配，`COM3 <-> COM4` 仅为下载 com0com 前的示例。若改用真实设备，需另行确认设备参数、编码、接线和断开/恢复方法。
- 功能实现完成后更新 `README.md`、`docs/user-manual.md` 和 `CHANGELOG.md` 中受影响内容；实现前不把尚未支持的功能写成已支持，也不修改 REQ-0001 原始正文。

## Acceptance criteria

- [ ] 清空同时清除显示、内存事件/时间戳历史、当前会话尾部、超长状态、诊断队列和点击时尚未显示的旧事件
- [ ] 会话锁和代次将清空前旧事件与清空后新事件分开；旧 reader 延迟返回不能越过清空边界发布数据
- [ ] 清空后新到达的数据可正常形成事件、显示并进入日志；清空不删除或修改任何既有日志文件
- [ ] 清空后切换显示设置不会恢复清空前内容
- [ ] 发送文本和 HEX 的原始字节行为保持正确，不自动追加 `0D 0A`
- [ ] 发送数据不进入接收事件队列，不显示为 `RX` 接收事件，不写入接收日志
- [ ] 覆盖连接关闭/异常重连、清空前尾部、清空时旧事件、清空后新事件的跨会话隔离测试
- [ ] 覆盖完整 PRD 验收标准 1-18，自动化测试在 Qt offscreen 下通过，并在干净依赖环境中复现
- [ ] 覆盖清空后日志文件保留、发送原始字节和日志故障隔离的回归行为
- [ ] 按项目现有流程运行完整测试套件并通过；真实串口验收步骤明确保留为 Windows 手工测试
