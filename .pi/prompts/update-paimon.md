## 必须遵守的发布原则

1. 保留所有旧提交和**更早版本**的标签。更早版本的 `vX.Y.Z` 标签不可删除、重建或改指向；但**当前正在发布版本**的标签，在发布内容需要修正时（例如把本次构建的 EXE 纳入同一版本）允许移动，并必须同步更新远端标签与发布说明。
2. 禁止使用 `git push --force`、`git push --force-with-lease`、`git reset --hard`、破坏性 checkout 或其他历史改写操作。
3. 本项目是**公开开源仓库**；发布前确认可见性符合预期即可。除非用户明确要求，不得擅自改为私有。
4. 除项目已跟踪的 `.pi/prompts/update-paimon.md` 外，不提交 `.pi/` 中的其他内容，也不提交 `.venv/`、缓存、`build/`、`dist/`、日志、认证文件、令牌、密码或其他本机文件。
5. **每次发布必须把构建的 EXE 复制到仓库根目录 `PaimonAssistant.exe` 并提交**，让标签指向的版本自带可下载的可执行文件；同时把 `SHA256` 写进发布说明。Gitee/GitHub Release 可以另外挂发布说明，但仓库内的 EXE 是主要交付途径。
6. 测试、构建或冒烟验证失败时，不得创建发布提交、标签或推送；先修复本次改动导致的问题。无法修复时保留现场并清楚报告。
7. 遇到远端分叉、合并冲突、权限不足、已有同名标签或不明确的用户改动时，停止危险步骤并说明阻塞，不得覆盖。

## 执行流程

### 1. 发布前检查

- 确认当前目录是派蒙助手仓库，读取项目规则、README、需求文档和相关源码。
- 检查 `git status --short --branch`、当前分支、远端地址、最近提交和全部版本标签。
- 执行 `git fetch origin --prune --tags`，确认本地与远端基线；不要自动丢弃或覆盖现有未提交改动。
- 区分本次需求相关改动和用户已有的无关改动，只处理并提交本次范围。
- 检查当前版本来源，包括 `paimon_assistant/__init__.py`、README、CHANGELOG 和最新可达的 SemVer 标签。

### 2. 自动确定新版本号

遵循 SemVer，并选择尚未使用的新标签：

- `PATCH`，如 `v0.1.0 -> v0.1.1`：修复错误、安全问题、兼容性优化或仅文档/维护更新。
- `MINOR`，如 `v0.1.0 -> v0.2.0`：增加向后兼容的新功能。
- `MAJOR`，如 `v0.2.0 -> v1.0.0`：存在明确的不兼容变更。

根据实际改动自动判断。若是否属于破坏性变更会影响用户数据、配置或既有使用方式，先向用户确认，不要自行发布重大版本。

### 3. 实现更新

- 先阅读相关实现和测试，明确行为与验收条件。
- 按现有项目结构完成最小且完整的实现，不进行无关重构。
- 为新增行为或修复补充针对性测试；缺陷修复应尽量先建立可复现测试。
- 更新必要的用户说明和需求文档，不虚构尚未实现或尚未验证的功能。

### 4. 更新发布资料

- 将 `paimon_assistant/__init__.py` 中的 `__version__` 更新为新版本。
- 更新 README 中的当前版本和受影响说明。
- 在 CHANGELOG 顶部新增本次版本，写明真实日期、功能或修复、验证结果和仍存在的限制；保留所有旧版本记录。
- 确认代码版本、README、CHANGELOG、提交信息和标签一致。

### 5. 完整验证

根据当前环境执行项目可用的全部验证，至少包括：

- Qt offscreen 完整自动化测试。
- 源码 `--smoke-test`。
- PyInstaller 干净打包。
- 打包后的 EXE `--smoke-test`。
- `git diff --check`。
- 敏感信息扫描和待提交文件清单检查。

没有真实串口或 com0com 时，不得声称真实串口验收通过；只报告自动化验证结果和未执行项。

### 6. 提交和发布

只有前述检查全部通过后才执行：

1. 把 `dist/PaimonAssistant.exe` 复制到仓库根目录 `PaimonAssistant.exe`，并确认它是最新构建（构建时间晚于全部源码改动）。
2. 仅暂存本次发布相关文件（含根目录 EXE），并检查完整 staged diff。
3. 创建提交：`release: Paimon Assistant vX.Y.Z`，正文概括本次功能、修复和验证。
4. 创建注释标签 `vX.Y.Z`，标签说明概括该版本功能与验证；标签必须指向包含 EXE 的提交。若当前版本已存在同名标签且本次需要修正发布内容，允许把该标签移动到新提交（更早版本标签仍不可动）。
5. 再次 `git fetch origin --prune --tags`，确认远端没有需要先处理的新提交，且推送是正常快进。
6. 使用非强制推送把发布分支和标签推送到 `origin`；标签移动场景下允许对该标签使用 `--force`（仅限当前版本标签），不得对其他 ref 强制推送。
7. 推送后核对远端分支、新标签解引用后的提交（确认含 `PaimonAssistant.exe`）、仓库可见性和本地工作树。
8. 创建或更新该标签的 GitHub Release 发布说明，写明本次新增功能、行为变更、验证结果，以及仓库内 EXE 的位置与 `SHA256`。
