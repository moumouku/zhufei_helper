 我推荐这套主题叫 「派蒙·石墨」：石墨灰背景、冷蓝色操作强调、清晰的等宽数据区，再用少量暖金保留派蒙的辨识度。整体参考 VS Code、JetBrains 的紧凑工作台，适合
 长时间看串口数据。

 结合现有 主界面代码，最值得优化的是：按“连接、接收、发送”组织控件，让接收数据成为视觉中心，同时明确当前解析模式。

 下面是具体设计方案。实施决定、分步范围、四条实施记录（第 1–4 步）和验证结果记录在文末；四个步骤均已完成。

 蓝色实心按钮使用 #0F131A 深色文字。已按 WCAG 公式计算：

 - 主文字 / 面板背景：约 13.0:1。
 - 次级文字 / 面板背景：约 7.3:1。
 - 时间戳 / 接收区背景：约 7.0:1。
 - 深色按钮文字 / 蓝色按钮背景：约 8.1:1。

 选中内容统一切换为主文字色，避免弱化文字在选中背景上对比度不足。以上是色值计算，实际 Qt 渲染仍需检查。

 布局建议采用 顶部连接栏 → 接收工具栏 → 大面积接收区 → 底部发送栏 → 状态栏。下面是已连接、分帧模式下的示意：

 ```text
   派蒙助手
   ──────────────────────────────────────────────────────────────────
   端口 [COM17 ▾]  波特率 [115200 ▾]  [串口参数 8N1 ▾]  [刷新]
   收发文本编码 [UTF-8 ▾]                                    [关闭]
   ──────────────────────────────────────────────────────────────────
   接收 [文本 ▾]   解析 [按 \r\n 分帧 ▾]   [✓ 时间戳]

   ──────────────────────────────────────────────────────────────────

   [09:12:03.125] sensor ready
   [09:12:03.168] temperature=26.4
   [09:12:03.211] voltage=3.30

                          接收数据区

   ──────────────────────────────────────────────────────────────────
   发送 [文本 ▾]  [输入要发送的内容______________________]  [发送]
   ──────────────────────────────────────────────────────────────────
   ● 已连接 COM17 · 115200 / 8N1          按 \r\n 分帧 · 日志已启用
 ```

 窗口足够宽时，连接参数和编码可以放在同一行。建议初始窗口约 1080 × 680 个 Qt 逻辑像素，并兼顾现有的 760 × 480 使用尺寸；接收区占可用高度的约 60%–70%。

 具体布局调整如下：

 1. 连接按钮靠近端口参数。
    当前“打开”混在接收、发送模式控制行中。把它移到连接栏，用户选择端口后就能直接完成连接。数据位、校验位和停止位收入“串口参数”展开区，收起时显示实际参数摘
    要，如 8N1。

 2. 接收与发送的设置各归其位。
    接收显示模式、解析模式、时间戳放在接收区上方；发送模式紧邻发送输入框。编码目前由收发共用，因此保留一个明确标为“收发文本编码”的入口。

 3. 把解析模式的影响说清楚。
    分帧模式的空白接收区显示：“等待完整帧，对端需以 \r\n 结束；未知协议可切换到原始字节。”
    原始字节模式显示：“收到即显示 · 不记录日志”，时间戳控件禁用并说明原因。这样可以减少“连接成功但软件没有反应”的误判。

 4. 状态栏持续显示事实。
    显示连接状态、端口、实际串口参数和日志状态。正常未连接用中性色；已连接用绿色加文字；日志失败用错误色加说明。主动选择原始字节属于正常工作状态，用中性提
    示表达“不记录日志”。

 5. 错误提示就近出现。
    接收诊断放在接收区上方，日志失败靠近日志入口。无错误时收起提示区域，避免空标签占用高度。状态提示要同时包含文字，方便快速判断原因。

 主按钮可以跟随操作阶段变化：未连接时突出“打开”，已连接时突出“发送”，“关闭”保持普通按钮样式。接收文本保持稳定，避免随数据到达闪烁。

 另外，当前界面每次收到数据都会滚到末尾。后续最值得补充的交互是“跟随最新”：用户向上查看历史时暂停自动滚动，点击“回到最新”后恢复；接收和日志继续运行。这涉及
 行为调整，适合在主题与布局完成后单独实施。

 在 PySide6 中，可以把颜色和尺寸集中为一张主题配置表，类似 C 中的配置结构体，再通过 QPalette 和局部 QSS 应用到控件。需要一并覆盖下拉菜单、提示框、滚动条、
 禁用态和焦点态，并把当前写死的 color: red 接入统一错误色。

 本方案采用以下假设，作为后续实施的决定记录：

 - A1. Windows / PySide6 单窗口工作台，接收区优先。——依据：项目定位与现有操作流程。
 - A2. 石墨灰、冷蓝、少量暖金；界面无衬线，数据等宽。——依据：开发者工具惯例与串口数据阅读需求。
 - A3. 保留现有收发共用编码、默认分帧和发送字节语义。——依据：现有代码及已确认的需求文档。
 - A4. 首轮落实主题、字体、控件分组与模式提示；随后改进历史阅读。——依据：当前界面的主要使用问题与实施范围。

## 已确认决定

以下决定已经用户确认，优先于上文示意中未明确的实现细节。

1. 串口参数采用折叠行：展开后显示现有数据位、校验位和停止位控件，收起后显示实际参数摘要（如 8N1），不做自定义弹出面板。
2. 第 2 步将初始窗口设为 1080 x 680、最小尺寸设为 760 x 480 个 Qt 逻辑像素；第 1 步不调整窗口尺寸或布局。
3. 错误提示区域使用 setVisible 控制显隐，无错误时不占高度；在第 3 步实施。
4. 状态栏在每次相关状态变化时，按当前连接、串口参数、解析模式和日志服务事实重新计算，不用历史失败标记把状态栏锁定为错误。不改变日志服务既有的失败熔断契约；当前仍处于熔断状态属于当前事实，不等于沿用过期的界面提示。
5. 同一时刻只有一个 primary：未连接时突出“打开”，已连接时突出“发送”，“关闭”使用普通按钮样式；动态切换在第 3 步实施。
6. 接收显示区和发送输入框均使用等宽字体。首版采用 Microsoft YaHei UI 界面字体（10 pt）和 Consolas 数据字体（11 pt），缺失时使用 Qt 系统字体回退，不引入字体文件或新依赖。
7. 替换 color: red 前检查颜色断言。已发现 4 处：tests/test_main_window_events.py 一处、tests/test_main_window_log.py 两处、tests/test_req0003_acceptance.py 一处。改为断言统一错误色，保留错误文案、状态和收发行为断言。

- A15. 自动暂停只由真实的用户滚动触发：监听滚动条 actionTriggered（滚轮/拖动/翻页/键盘）设用户意图标志，由紧随其后的 valueChanged 消费；程序性 setValue（含 Qt 延迟布局自己调整滚动条）不改变跟随状态。渲染与窗口缩放后用 singleShot(0) 落定最终位置（generation 语义，仅最新一次生效）。——依据：原生实测发现 setPlainText 后 Qt 会在下一轮事件循环按文本光标（重置到 0）执行可见性调整，把跟随态拉离末尾、把暂停态拉回顶部；若把这类程序性变化视为用户上翻，会在冷启动/切换模式/缩放后误暂停。
