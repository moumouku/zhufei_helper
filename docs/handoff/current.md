## 口径
最终产品决定集中记录在 `docs/requirements/REQ-0005-oscilloscope.md` §14，具体契约以该文档为准。特别注意：

- 数据页与波形页共用物理串口，但同时仅当前页可接收；接收时禁止切页，停止会关闭串口并丢弃缓冲，切页后另一页默认停止且需用户手动开始。两页历史、分帧、解析和清空互相隔离。
- 数据页“原始字节”不做任何波形解析。示波器自己按 `\r\n` 分帧，严格解析 1～8 个不含空格的有符号十进制 int32；合法完整帧产生点，非法完整帧显示失败并写 RX 日志但不产生点。
- X 轴和数据显示用单调时钟相对时间；现有 RX 日志用主机本地绝对时间。主机接收时刻不代表 MCU 采样时刻。
- 停止后重新开始延续同一采集时间原点和历史，停止期间不接收、不缓存；只有清空/新建采集才清历史并重置原点。端口或串口参数变更不清历史，需写连接边界。
- 最近 180 秒内的原始采样点全部保留；只能对图表绘制降采样，不能删原始点。资源不足应停止接收并保留已有数据。帧数据区同样保留 180 秒，窗口淘汰由新样本时间推进，停止期间不按墙上时间清理。
- 通道按会话见过的最大字段数递增；短帧的缺少字段形成曲线断点，不沿用旧值。清空后重新推断；显示通道共用 Y 轴。
- 图表支持 X/Y 独立缩放、自动缩放、回到最新、拖拽平移、历史视图及悬停读值；纵轴限于 int32，横轴受当前三分钟保留窗口限制。
- 被否决的方案：两个页面同时消费/广播同一数据（违反互斥且造成历史串扰）；进入波形页强制把数据页改成分帧模式（破坏原始模式语义）；按采样序号或本地墙上时间作波形横轴（分别丢失真实到达间隔或受系统时钟跳变影响）；对原始点做降采样/点数截断（违反全量保留决定）；暂停时继续缓存串口输入（与关闭通道、恢复后只收新数据的决定冲突）。

## 坑
- 现有接收控制器只维护 REQ-0003 事件队列和 REQ-0004 原始字节队列，还没有页面消费者所有权/独立示波器会话接口；实现时不能让两个页面轮询同一队列。
- 停止并重开串口还需核实 pyserial/驱动输入缓冲清除行为；需求要求旧数据不得补收。要覆盖 `reset_input_buffer()` 行为和读线程/队列同步边界。
- 每帧的单调时间与墙上时间必须在接收线程的完整帧识别点关联记录，不能用 UI 定时器消费队列的时刻代替。
- 短帧缺少的通道必须制造 NaN/分段等可断线表示；否则 QtCharts 会把前后有效点直线连接，造成虚假波形。
- REQ-0005 已提到 QtCharts 不需新增运行时依赖；本地 `.venv` 的 PySide6 6.11.1 可导入 QtCharts，但仍应在声明支持的最低 PySide6 版本和 PyInstaller 干净构建中验证。
- README 和使用说明现在描述 v0.5.0 已发布行为（当前尚无波形页），不是新需求权威；实现结束后再按 REQ-0005 §13.4 同步更新，避免在实现前宣称功能已支持。
