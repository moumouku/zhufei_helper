## 1. 目标

派蒙助手目前只在启动时枚举一次串口，之后依赖用户手动点击「刷新」才能发现新插入的设备；设备被拔出时也没有主动感知，只能等读写失败后才报错。本需求为派蒙助手加入自动监测新插入串口的功能：每隔约 1 秒检测一次串口列表，新 COM 口自动加入列表并按规则选中，被拔出的端口自动从列表移除，当前连接的端口被拔出时自动关闭连接并提示。

监测只做「感知和列表管理」，绝不自动打开任何端口，避免误连其他串口设备。

## 2. 用户故事

1. 作为串口调试用户，我希望软件每隔约 1 秒自动检测一次串口列表，以便新插入的设备无需手动点击刷新即可被发现。
2. 作为串口调试用户，我希望新插入的 COM 口自动加入端口下拉列表，以便直接选择打开。
3. 作为串口调试用户，当端口列表为空或当前选中端口已失效（被拔出）时，我希望新端口自动被选中，以便最快打开新设备。
4. 作为串口调试用户，当我已经选好一个有效端口（包括启动时程序默认选中的端口）时，我希望新端口只加入列表而不改变我的选择，以便不会误连。
5. 作为串口调试用户，我希望自动监测绝不自动打开任何端口，以便避免误连其他串口设备。
6. 作为串口调试用户，当正在连接的端口被拔出时，我希望软件自动关闭连接并弹窗提示，以便我知道连接已中断、无需手动关闭。
7. 作为串口调试用户，我希望拔出判定有约 2 秒去抖，以便设备复位或驱动重枚举造成的短暂消失不会被误报为拔出。
8. 作为串口调试用户，我希望拔掉未选中的端口时只是静默从列表移除，以便不被打扰。
9. 作为串口调试用户，当我选中的（未连接）端口被拔出时，我希望它从列表移除且不自动改选其他剩余端口，以便我明确知道当前没有选中，避免误开其他端口。
10. 作为串口调试用户，我希望一次插入多个新端口时选中枚举顺序中的第一个，以便行为可预测。
11. 作为串口调试用户，我希望连接打开期间端口列表数据仍持续更新（下拉框保持禁用），以便关闭连接后新端口立即可见。
12. 作为串口调试用户，我希望手动「刷新」按钮仍然可用，以便需要时立即刷新。
13. 作为串口调试用户，我希望读取线程报错仍按原有逻辑立即关闭并提示、不受拔出判定去抖影响，以便真正的读写错误不被延迟处理。

## 3. 功能需求

1. 软件启动后以约 1 秒间隔自动轮询可用 COM 口列表；窗口关闭时停止轮询。不提供开关 UI，监测常开。
2. 轮询结果与上一次快照做差量更新端口下拉列表（只增删变化的项，不清空重建）；手动「刷新」按钮与轮询共用同一差量更新路径。
3. 发现新 COM 口时：
   - 当前选中为空或已失效（该端口已不在列表中）→ 自动选中新端口；多个新端口同时出现时选中枚举顺序的第一个；
   - 当前选中有效（包括启动时程序默认选中的端口）→ 只加入列表，不改变选择。
4. 自动监测只负责加入和选中，绝不自动打开端口。
5. 已选中但未连接的端口被拔出：从列表移除，不自动补选剩余端口，选中项留空。
6. 未选中的端口被拔出：静默从列表移除，不弹窗。
7. 正在连接的端口被拔出：连续两次轮询（约 2 秒）均查不到该端口时判定拔出，自动关闭连接并弹窗提示「串口已拔出，连接已关闭」；判定期间端口重新出现则取消判定、恢复正常。
8. 读取线程报错路径保持现状（立即关闭并提示），不受拔出判定的去抖影响。
9. 连接打开期间轮询继续更新列表数据；端口下拉框仍处于禁用状态。

## 4. 技术约束

| 层级 | 方案 |
|---|---|
| 运行平台 | Windows 10 / 11 |
| Python | Python 3.10 / 3.11 |
| GUI | PySide6 6.6+ |
| 串口通信 | pyserial 3.5+ |
| 打包 | PyInstaller 6.x |
| 应用名称 | 派蒙助手 |
| 可执行文件 | `PaimonAssistant.exe` |

pyserial 不提供热插拔事件机制，串口变化检测通过定时轮询 `list_ports()` 实现；该调用在 Windows 上开销极小，1 秒间隔可忽略。轮询、差量、去抖逻辑运行在 Qt 主线程（QTimer 驱动），不新增线程。

## 5. 实施决策

1. 新增纯 Python 模块 `paimon_assistant/port_monitor.py`，提供 `PortMonitor` 类（无 Qt 依赖，可独立测试）：
   - 注入 `port_lister` 回调（默认与 `SerialController` 同一数据源）；
   - 接口：`tick()`（枚举一次并与上次快照差量、驱动事件）、`set_connected(port)` / `clear_connected()`（标记当前连接端口，拔出判定的对象）；
   - 事件回调：`on_added(ports)`、`on_removed(ports)`、`on_lost(port)`；
   - 内部状态：上次端口快照、连接端口的缺失计数（连续 2 次缺失触发 `on_lost`，中途恢复清零）。
2. `SerialController` 保持不变；`available_ports()` 继续作为轮询数据源。
3. `MainWindow` 接线：新增 1000ms `QTimer` 驱动 `monitor.tick()`；事件处理实现 UI 策略（差量更新下拉框、规则 3/5/6 的选中逻辑、`on_lost` 时关闭连接并弹窗）；`closeEvent` 停止定时器；手动「刷新」按钮与轮询共用差量更新代码路径。
4. 拔出提示沿用现有 `QMessageBox.warning` 风格（模态、需确认）。
5. 不新增监测开关、间隔配置等 UI；不自动打开端口。

## 6. 测试决策

1. 好测试的标准：只测外部可观察行为（枚举结果、事件序列、列表内容、选中项、关闭调用与弹窗），不测内部实现细节（快照字段、计数变量等）。
2. `PortMonitor` 单元测试（新建 `tests/test_port_monitor.py`）：注入 fake port lister（参照 `tests/test_serial_controller.py` 的 `FakePortLister` 模式）。覆盖：差量增/删事件、连续两次缺失才触发 `on_lost`、判定期间恢复则取消、连接端口跟踪（`set_connected`/`clear_connected`）、多个端口同时插入、事件顺序与幂等（相同快照不产生事件）。
3. `MainWindow` 行为测试（扩展 `tests/test_main_window.py`）：沿用 `FakeController`（ports 可变）与 `dialogs` fixture。覆盖：新端口自动加入并选中（选择为空/失效时）、有效选择不被打断、拔出已连接端口触发一次 `close()` 与一次 warning 弹窗、拔未选中端口无弹窗、拔选中（未连接）端口后不补选、打开期间列表仍更新、启动枚举与手动刷新行为回归。
4. 全部测试运行于 Qt offscreen 环境与 fake 串口，不依赖真实硬件。

## 7. 范围外

- 不自动打开端口、不做多连接管理。
- 不提供监测开关、轮询间隔配置等 UI。
- 不使用 Windows 驱动级热插拔事件（`WM_DEVICECHANGE`），仅轮询。
- 不持久化端口配置。
- 不处理设备协议解析。
- 逻辑与平台无关，但仅承诺 Windows 10 / 11 验收。

## 8. 实施与交付约束

1. 开发采用 TDD：先编写能够准确失败的测试，再实现最小代码使其通过，最后重构并运行完整测试。
2. 需要委派时，subagent 使用 `deepseek-v4-flash`；长任务每 5 分钟检查一次运行状态。
3. 自动化测试使用 fake serial / fake port lister 和 Qt offscreen 环境，不依赖真实串口或显示器。
4. 随代码更新 README、CHANGELOG 与用户手册（`docs/user-manual.md`）。
5. 无真实串口时，使用 com0com 创建虚拟串口对进行热插拔场景端到端手工验收。

## 9. 验收标准

1. 插入新的虚拟串口后，约 1 秒内自动出现在端口列表；列表为空或当前选中已失效时自动选中，已有有效选择（含启动默认选中）时不切换选择。
2. 打开连接后拔掉该端口：约 2 秒内自动关闭连接并弹窗提示；1 秒内恢复的瞬断不触发误报。
3. 拔掉未选中端口：静默移除、无弹窗；拔掉选中但未连接端口：从列表移除且不自动改选剩余端口。
4. 连接打开期间端口列表数据持续更新，下拉框保持禁用；关闭连接后新端口立即可见。
5. 手动「刷新」按钮行为不变；启动自动枚举行为不变。
6. 全部自动化测试通过（新增 + 既有回归）。
