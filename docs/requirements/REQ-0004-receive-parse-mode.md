## 1. 背景与目标

REQ-0003 把接收链路固定为严格 `\r\n` 分帧，并明确覆盖 REQ-0001 的"接收端只传递裸字节"范围（REQ-0003 §12.2），同时禁止双轨兼容路径（§5.1.6）。

实际使用暴露出该单一模式的易用性问题：派蒙助手是**通用串口调试助手**，没有固定协议。当对端不发送 `\r\n`（例如只发 `hello`，或只发 `\n`）时，接收区完全不显示任何内容，用户无法区分"设备没发数据"和"数据到了但没有帧结束符"。真实 com0com 验证已确认该现象（文本模式下输入字面量 `\r\n` 实际发出的是 4 个普通字符 `5C 72 5C 6E`，不构成结束符）。

本需求增加**接收解析模式选择**：既保留 REQ-0003 的事件化接收链路，又提供一条"收到即显示"的原始字节路径。

## 2. 与 REQ-0003 的关系

1. 本需求**显式覆盖** REQ-0003 §5.1.6 中"不增加双轨兼容路径"的约束：现在允许同时存在事件通道与原始字节通道。
2. 本需求**显式覆盖** REQ-0003 §12.2 中"覆盖 REQ-0001 接收层范围"的排他性表述：两种模式按用户选择生效，而不是只保留分帧一种。
3. REQ-0003 的其余全部条款（分帧规则、事件协议、时间戳、显示格式、日志、保留清理、日志目录入口、故障隔离、清空线性化、发送行为）在**"按 `\r\n` 分帧"模式**下保持不变。
4. 不修改 REQ-0001、REQ-0003 正文。

## 3. 接收解析模式

界面新增"接收解析"选择控件，提供两种模式：

| 模式 | 行为 |
|---|---|
| 按 `\r\n` 分帧（默认） | 完全遵循 REQ-0003：严格 `0D 0A` 边界、生成 `ReceivedEvent`、写入 `RX` 日志、支持时间戳与超长帧诊断 |
| 原始字节 | REQ-0001 行为：读取到的字节块到达即进入显示历史，不生成 `ReceivedEvent`、不写 `RX` 日志、不进行超长帧判定 |

### 3.1 控件

1. 控件类型为 `QComboBox`，对象名 `parse_mode_combo`。
2. 选项文本固定为 `按 \r\n 分帧` 与 `原始字节`，顺序如上。
3. **默认选择"按 `\r\n` 分帧"**，且不记住用户上次的选择（每次启动都回到默认）。
4. "接收解析"只在接收链路生效，不改变发送行为。

### 3.2 原始字节模式的行为

1. 串口读取到的每个字节块按到达顺序追加到原始字节历史。
2. 显示内容按当前"接收"模式（文本/HEX）与"编码"（UTF-8/GBK）渲染：
   - 文本模式：用当前编码解码全部原始字节；跨读取块被拆开的多字节字符保持待定，直到后续字节补齐（不提前输出替换字符）。
   - HEX 模式：全部原始字节渲染为大写、两位一组、空格分隔；**不追加** `0D 0A`，也不按行分隔。
3. **不使用帧结束符**：任意字节（含单独 `\r`、单独 `\n`、`\r\n`）都只是普通内容，不触发事件、不分行。
4. 原始字节模式下**不产生接收事件**，因此：
   - 不写入 `RX` 日志；
   - "时间戳"开关不适用（控件在该模式下禁用，显示不带时间戳前缀）；
   - 不产生超长帧诊断（该模式不做超长判定）；
   - "清空"以外的历史管理行为不变。
5. 原始字节历史保存在内存中，与事件历史相互独立；`清空` 同时清除两者。

### 3.3 模式切换

1. 切换接收解析模式时，**重置"按 `\r\n` 分帧"模式分帧器中尚未完成的尾部字节**，避免切换期间的字节与切换前遗留的尾部拼接成错误事件。
2. 切换模式**不清空**已经积累的历史：事件历史与原始字节历史各自保留，切换后按新模式的当前设置重新渲染显示。
3. 切换模式不改变已写入的日志文件，不触发日志写入，不影响串口连接。

### 3.4 队列与接口契约

1. `SerialController.received_queue` 仍然只放 `ReceivedEvent`；原始字节模式不使用该队列。
2. 新增 `SerialController.raw_queue`，只放 `bytes` 原始读取块；只在原始字节模式下产生数据。
3. 新增 `SerialController.set_raw_mode(enabled: bool) -> None`：
   - 在会话锁内更新模式标记；标记在控制器上持久化，后续 `open()` 创建的新会话沿用该标记；
   - 模式真正发生变化时重置当前分帧器的未完成尾部（§3.3.1）；
   - 控制器未打开时调用必须安全，不创建串口连接、不抛异常。
4. `reset_receive_session()` 同时替换并清空 `received_queue`、`raw_queue` 与 `diagnostic_queue`，并重置分帧器；语义与 REQ-0003 §10.1 一致。
5. reader 线程只做串口读取与队列发布：原始字节模式只做 `raw_queue.put`，不执行文件 I/O、不写日志、不依赖日志状态。

## 4. 清空行为

点击"清空"时在 REQ-0003 §10 的基础上额外清除：

1. 原始字节历史；
2. 原始字节队列中点击时尚未显示的数据。

清空后新到达的数据按当前模式进入新的接收链路。清空不删除、不修改任何已写入的日志文件。

## 5. 日志

1. `RX` 日志只记录"按 `\r\n` 分帧"模式生成的完整接收事件，格式与保留规则完全沿用 REQ-0003 §7、§8。
2. "原始字节"模式不写 `RX` 日志。
3. 日志故障隔离语义不变（REQ-0003 §7.3）。

## 6. 验收标准

1. "接收解析"控件为 `QComboBox`，对象名 `parse_mode_combo`，两个选项文本与顺序符合 §3.1。
2. 启动默认选择"按 `\r\n` 分帧"，且不持久化选择。
3. 原始字节模式下，不含任何 `\r`/`\n` 的字节（如 `hello`）到达后**立即显示**，无需等待结束符。
4. 原始字节模式下，单独 `\r`、单独 `\n`、`\r\n` 都不触发分帧或分行，仅作为普通内容显示。
5. 原始字节模式下切换文本/HEX 与 UTF-8/GBK，全部历史正确重绘；跨读取块被拆开的多字节字符不出现替换字符。
6. 原始字节模式不产生接收事件、不写 `RX` 日志文件。
7. 原始字节模式下时间戳控件被禁用且显示不带时间戳前缀。
8. 分帧模式下全部 REQ-0003 行为不变（分帧、时间戳、日志、超长帧诊断、清空线性化）。
9. 切换接收解析模式会重置分帧器未完成尾部：切换前遗留的尾部不会与切换后数据拼成事件。
10. 切换接收解析模式不清空已积累的两种历史；切换后按新模式重新渲染。
11. 原始字节模式下的数据在切换到分帧模式后，不会变成接收事件，也不写日志（两种通道互不污染）。
12. `reset_receive_session()` 同时清空事件队列、原始字节队列与诊断队列；清空后新数据按当前模式正常进入链路。
13. `received_queue` 仍然只提供 `ReceivedEvent`；`raw_queue` 只提供 `bytes`。
14. 发送行为不变：不自动追加 `0D 0A`，发送数据不进入任何接收通道、不显示为 `RX`、不写日志。
15. 自动化测试使用 fake serial、fake 时间源、临时日志目录与 Qt offscreen；真实 com0com 端到端验证作为可重复的手工验收脚本保留在 `tests/` 下，默认跳过、显式启用时执行。
