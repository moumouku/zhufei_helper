# 派蒙助手 AI 更新与发布命令

派蒙助手项目已配置可复用的 pi 命令：

```text
/update-paimon <本次更新内容>
```

每次更新只需要在命令后写本次要实现的内容，不需要重复说明测试、版本号、提交、标签、私有仓库和防覆盖规则。

## 使用示例

修复问题：

```text
/update-paimon 修复串口意外断开后无法重新连接的问题
```

增加功能：

```text
/update-paimon 增加接收时间戳开关，默认关闭，并记住用户上次的选择
```

同时发布可执行文件：

```text
/update-paimon 增加接收内容保存功能，并把新版本 EXE 上传到对应的 GitHub Release
```

如果命令后没有内容，AI 只会询问本次要更新什么，不会自行猜测需求。

## 命令会自动完成的工作

1. 检查当前工作树、远端、已有提交和版本标签。
2. 保留用户已有改动，只实现本次需求。
3. 根据改动自动选择新的 SemVer 版本号。
4. 修改代码并补充测试。
5. 更新程序版本、README 和 CHANGELOG。
6. 运行完整测试、源码冒烟测试、干净打包和 EXE 冒烟测试。
7. 把本次构建的 EXE 复制到仓库根目录 `PaimonAssistant.exe`，并纳入发布提交，使标签指向的版本自带可下载的可执行文件。
8. 扫描敏感信息并检查待提交文件。
9. 创建发布提交和注释标签；标签必须指向包含 EXE 的提交。
10. 以非强制方式推送分支和标签。
11. 为新标签创建或更新 GitHub Release 发布说明，写明仓库内 EXE 的位置与 SHA256。
12. 推送后核对远端提交、标签和工作树状态。

## 版本号规则

| 改动类型 | 示例 | 版本变化 |
|---|---|---|
| 修复、兼容性优化、文档维护 | 修复重连错误 | `v0.1.0 -> v0.1.1` |
| 向后兼容的新功能 | 增加保存接收内容 | `v0.1.0 -> v0.2.0` |
| 不兼容的重大变化 | 更换配置格式且无法兼容旧格式 | `v0.2.0 -> v1.0.0` |

## 旧版本保护

该命令明确禁止：

- `git push --force` 或 `git push --force-with-lease`
- 改写 Git 历史
- 删除或改指向**更早版本**的标签
- 将公开仓库擅自改成私有（本项目就是公开开源项目）
- 除项目模板 `.pi/prompts/update-paimon.md` 外，把 `.pi/` 的其他内容、`.venv/`、缓存、日志、凭据或本机文件提交进仓库
- 提交 `build/`（PyInstaller 中间产物）与 `dist/`（本地构建输出目录）；这两个目录已由 `.gitignore` 忽略

该命令要求并允许的做法：

- **每次发布必须把构建产物复制到仓库根目录 `PaimonAssistant.exe` 并提交**，让标签指向的版本自带可直接下载的可执行文件；发布提交里要包含这个文件。
- 仓库为公开开源项目（`moumouku/zhufei_helper`），可见性不是发布前提；发布前确认可见性符合预期即可。
- 当**当前正在发布的版本**内容需要修正（例如把 EXE 纳入同一版本、补充发布说明）时，允许把该版本标签移动到修正后的提交；移动后必须同步更新远端标签与发布说明。

正常更新只在历史后面增加新提交和新标签，例如：

```text
v0.1.0 -> 初始版本提交
v0.1.1 -> 后续修复提交
v0.2.0 -> 后续功能提交
```

GitHub 默认页面会显示 `main` 的最新内容；每个版本标签都指向包含该版本源码与 `PaimonAssistant.exe` 的提交，使用者无论从 `main` 还是从标签获取，都能拿到可运行的程序。

## 项目模板位置

```text
E:\projects_learning\zhufei_helps\.pi\prompts\update-paimon.md
```

文件名决定命令名，因此 `update-paimon.md` 对应 `/update-paimon`。该命令只属于派蒙助手项目，不会出现在其他项目中。pi 只会为已信任的项目加载 `.pi/prompts/`；如果当前会话的命令自动补全尚未显示它，请确认项目已受信任并重新启动一次 pi。
