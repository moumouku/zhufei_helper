# 派蒙助手使用说明书

## 1. 软件简介

派蒙助手是一款 Windows 串口调试上位机，适用于嵌入式设备、开发板和串口模块的收发调试。

“数据”页只负责原始字节的收发和显示，不解析设备协议；接收数据可以按文本或 HEX 显示，发送数据也可以选择文本或 HEX。源码与当前分支的 v0.6.0 开发构建新增独立的“波形”页，按十进制数值协议解析并绘制波形；下载见 2.1。

## 2. 启动软件

直接下载含波形页的 v0.6.0 单文件程序：

当前分支根目录的 EXE 与源码均为 v0.6.0 开发构建，已包含“波形”页。最新正式 [GitHub Release](https://github.com/moumouku/zhufei_helper/releases/tag/v0.5.0) 仍为 v0.5.0，不包含波形页。

## 3. 主界面

当前源码开发版本的主界面顶部提供“数据”和“波形”两个页面标签，启动默认进入“数据”页，两页初始都不接收。两页共用连接栏的端口、波特率、串口参数和“收发文本编码”，也共用发送区；但同一时刻只有一页可以接收串口数据，活动接收期间不能切换页面（详见第 7 节）。

“数据”页按四个操作区域组织：

1. 连接栏：端口、波特率、打开/关闭、串口参数、刷新，以及共用的“收发文本编码”。窗口宽度足够时排成一行，缩窄时自动排成两行。
2. 接收工具栏：接收显示模式、解析模式、时间戳开关，以及“清空接收”“日志目录”按钮。
3. 接收显示区：显示完整的接收事件（含可选时间戳），并在上方显示接收诊断提示。
4. 发送栏：发送模式、等宽输入框和发送按钮。

“波形”页由自己的工具栏（开始/停止接收、清空波形、日志目录、跟随最新、自动缩放、回到最新、X+/X-/Y+/Y-）、诊断与日志错误提示、数据显示区、波形图和右侧通道栏组成，详见第 7 节。

默认窗口为 1080 x 680，最小为 760 x 480；尺寸按逻辑像素计算，实际显示随 Windows 缩放设置调整。

窗口底部状态栏持续显示连接状态、当前连接的端口与串口参数，以及解析模式和日志状态。未连接使用中性色；已连接使用绿色文字。主操作同时只有一个：数据页未连接时突出“打开”，波形页停止时突出“开始接收”，活动接收时突出“发送”；“关闭”和“停止接收”保持普通按钮样式。

接收诊断紧邻接收显示区，日志错误靠近“日志目录”入口。无错误时提示区域隐藏，不占用高度；单个未完成帧超过 1 MiB 时显示红色的“接收帧超过 1 MiB，已丢弃”，点击“清空接收”后隐藏。

软件启动时会自动枚举当前可用串口。启动后软件以约 1 秒间隔持续监测串口变化，发现新端口会自动加入列表；点击“刷新”仍可以立即执行一次枚举。监测只更新列表和选择，不会自动打开端口。

## 4. 串口参数

### 4.1 端口

“端口”下拉框显示系统当前检测到的 COM 口。当前开发环境的 com0com 配对口为：

```text
COM17
COM19
```

端口号由 Windows/com0com 分配，其他环境可能不同；`COM3`、`COM4` 仅作为早期示例。

如果列表为空，需要先连接设备，或者安装并创建虚拟串口。当前选择有效时，新插入端口不会改变选择；当前选择为空或已失效时，会自动选择本次枚举顺序中的第一个新端口。拔出未选中的端口会静默移除；拔出已选中但未连接的端口后，选择会留空，不会自动补选其他端口。

### 4.2 波特率

预置档位：

```text
9600
19200
38400
57600
115200
230400
460800
921600
```

波特率下拉框可以手动输入其他正整数。

### 4.3 高级参数

点击连接栏的“串口参数 8N1”展开数据位、校验位和停止位设置，再次点击即可收起。按钮始终显示当前参数摘要，例如 `7E1.5`。展开或收起不会重置参数；连接后仍可展开查看，但参数下拉框保持禁用。

默认值为 `8 / N / 1`：

| 参数 | 可选值 | 默认值 |
| --- | --- | --- |
| 数据位 | 5、6、7、8 | 8 |
| 校验位 | N、E、O、M、S | N |
| 停止位 | 1、1.5、2 | 1 |

常见设备参数为 `115200 / 8 / N / 1`。

## 5. 打开和关闭串口

1. 选择有效 COM 口。
2. 设置波特率和高级参数。
3. 点击“打开”。
4. 打开成功后按钮显示“关闭”，串口配置控件会暂时禁用。
5. 再次点击“关闭”即可断开串口。

如果端口不存在、被其他程序占用或设备已经断开，软件会弹出错误提示，并恢复到可以重新选择串口的状态。打开连接期间端口列表仍会持续更新，端口下拉框和串口参数保持禁用，但“刷新”按钮仍可用。已连接端口连续两次约 1 秒轮询都不可见时，软件会自动关闭连接并提示“串口已拔出，连接已关闭”；端口在第二次轮询前恢复时不会误报。

## 6. 接收数据

### 6.1 文本模式

“接收”选择“文本”时，接收字节会按照连接栏的“收发文本编码”选择解码；同一个编码设置也用于发送文本。

支持两种编码：

- `UTF-8`
- `GBK`

编码必须和设备发送数据时使用的编码一致，否则中文可能显示为替换字符或乱码。

文本模式显示的是完整事件的载荷（不包含末尾的 `\r\n`）。跨串口读取块的完整字符由接收分帧在结束边界处拼接，不会因为一次 `read` 被拆开而丢失字符。

### 6.2 HEX 模式

“接收”选择“HEX”时，每个字节显示为大写的两位十六进制，并使用空格分隔。

HEX 模式显示的是完整原始帧，因此末尾一定包含结束符 `0D 0A`。

例如设备发送 `Hello\r\n` 时：

```text
显示内容：48 65 6C 6C 6F 0D 0A
```

HEX 模式适合检查协议帧、控制字节、零字节和非文本数据。

### 6.3 接收解析：协议分帧还是原始字节

接收工具栏的“解析”决定收到的串口字节如何进入显示，两种模式：

| 模式 | 适合场景 | 行为 |
| --- | --- | --- |
| 按 `\r\n` 分帧（默认） | 对端以 `\r\n` 结束每一帧 | 严格帧分帧，每条完整帧是一条接收事件，带时间戳并写入 `RX` 日志 |
| 原始字节 | 调试未知协议，或对端不发送 `\r\n` | 收到什么就显示什么，不分帧、不分行、不写日志 |

空白接收区会按模式显示操作提示：分帧模式提醒等待完整帧、对端需发送结束符；原始字节模式提示“收到即显示 · 不记录日志”。这些说明不会成为接收数据或日志内容。

**这是最容易让人误以为“软件坏了”的地方，请注意：**

- “按 `\r\n` 分帧”模式下，**没有结束符的数据不会显示**，也不会写日志。对端只发 `hello` 不发 `\r\n` 时，接收区一直是空的。
- 单独的 `\n`（LF）**不算**结束符，不会分帧。
- 需要确认“到底有没有数据到达”时，切到“原始字节”模式。
- 派蒙助手**不会回环显示自己发送的数据**：你发送的内容只会送到对端，不会出现在接收区。要看到接收内容，必须由对端（另一端串口程序或设备）发送数据。

### 6.4 接收分帧与时间戳

以下内容适用于“按 `\r\n` 分帧”模式。

接收端只按连续两个字节 `0D 0A`（即 `\r\n`）识别数据帧结束，并把每个完整帧当作一个接收事件：

- 单独的 `\r` 不结束帧，软件会等待后续字节。
- 单独的 `\n` 不结束帧，作为普通载荷字节保留。
- `\r\r\n` 中，前一个 `\r` 属于载荷，最后两个字节 `\r\n` 才是结束边界。
- 空帧 `\r\n` 是合法事件，载荷为空。
- 软件不对其他换行形式做自动转换；载荷内部如果出现 `\r\n`，会被当作一次帧结束。

“时间戳”开关控制每个事件在显示时是否带前缀：

```text
[09:12:03.125] Hello
[09:12:04.006] World
```

时间格式固定为本地时间 `HH:mm:ss.SSS`。时间戳在软件读到该事件结束边界时记录，表示识别到帧结束的时间，而不是界面刷新的时间。

时间戳开关默认开启，且不记住上次的选择。“原始字节”模式下该开关会被禁用，悬停说明该模式不生成接收事件，因此没有逐帧时间戳；切回分帧模式后恢复可用，并保留切换前的勾选状态。关闭开关只会去掉显示前缀，不会改变接收、事件历史或日志内容；重新打开后会按当前设置重绘全部已完成事件。

切换接收解析模式不会清空已积累的历史：两种模式各自保留自己收到的数据，切回去仍然可以看到。

### 6.5 跟随最新

接收区工具栏的“跟随最新”默认开启。接收区追加新数据后会自动显示最新内容；窗口尺寸变化时也会保持最新内容可见。

需要查看旧数据时，可以用鼠标滚轮或滚动条向上浏览。用户离开底部后，按钮会自动变为“回到最新”，新数据仍会继续接收、显示并写入日志，但不会把阅读位置强行拉回末尾。即使停在底部，手动点击“跟随最新”也可以主动暂停跟随。

点击“回到最新”会立即滚到末尾并恢复跟随。切换文本/HEX、编码、时间戳或解析模式时，暂停状态不会被偷偷恢复；同一解析模式会尽量保留当前阅读位置和有效选区，两种解析模式分别记住各自的位置。格式变化导致文本长度改变时，位置按比例近似恢复，选区可能被清除。

点击“清空接收”会清除阅读位置并恢复“跟随最新”。

### 6.6 清空接收区

点击“清空接收”会同时清除：

- 当前接收显示内容
- 内存中的完整接收事件和时间戳历史
- 原始字节历史（“原始字节”模式积累的内容）
- 解析器中尚未完成的尾部字节和超长帧丢弃状态
- 点击清空时尚未显示的待处理旧接收事件
- 接收诊断提示

清空是原子操作：清空前未完成的数据不会与清空后到达的数据拼接。清空后新到达的数据仍会正常显示并写入日志。清空**不会**删除或修改任何已经写入的日志文件。

### 6.7 接收日志

软件会把每个完整接收事件自动写入按日期划分的日志文件：

```text
%LOCALAPPDATA%\PaimonAssistant\logs\YYYY-MM-DD.txt
```

- 文件使用 UTF-8 编码，每个事件占一行。
- 日期只出现在文件名中，记录行不重复写年月日。
- 日志固定记录完整原始帧的 HEX（大写、两位一组、空格分隔），**不受**界面文本/HEX 模式、编码选择或时间戳开关影响。

记录格式与示例：

```text
[09:12:03.125] RX 48 65 6C 6C 6F 0D 0A
```

空帧记录为：

```text
[09:12:03.125] RX 0D 0A
```

用户发送的数据不写入接收日志。

日志只记录“按 `\r\n` 分帧”模式生成的完整接收事件；“原始字节”模式收到的数据**不写日志**。需要用日志留存原始流时，请使用“按 `\r\n` 分帧”模式并让对端发送 `\r\n` 结束符。

日志目录默认保留当天及此前 30 个日历日的文件。软件在启动时执行一次清理，并在跨过本地日期后的首次写日志前再次清理；日期在文件名中不合规的文件、子目录和其他文件不会被删除。日志目录不存在时启动清理会直接跳过，不会为此单独创建目录。

点击“日志目录”按钮会自动创建日志目录（如果尚不存在），并用资源管理器打开该日志目录本身。真实串口端到端验收仍需在安装了虚拟串口驱动或连接了实际设备的 Windows 环境中手工执行。

状态栏的日志状态按当前模式和日志服务状态显示：分帧模式下默认“日志已启用”，写入停止后显示红色“日志写入失败”；切到原始字节时显示中性的“不记录日志”，切回分帧后重新反映当前写入状态。

点击“日志目录”时若目录或资源管理器打开失败，会在入口附近显示具体原因，不会因此停止日志写入。再次成功打开目录后，过期的目录错误提示会清除；若日志写入此前已经停止，写入失败提示继续保留。

如果记录接收事件时日志目录创建失败、日志文件无法打开或写入失败，软件会：

- 在界面显示红色提示“日志写入失败，请检查磁盘空间或权限”；
- 停止本次运行期间后续的日志写入，不缓存、不重试；
- 继续正常接收、生成事件、刷新显示和执行其他串口操作。

日志只是辅助记录，不会成为串口接收功能的单点故障。

## 7. 波形页（示波器）

“波形”页已包含在本分支的 v0.6.0 EXE 和源码中，用于接收并绘制以 `\r\n` 结束的十进制数值波形协议。

### 7.1 页面、接收互斥与切换

- 主窗口顶部有“数据”和“波形”两个标签，启动默认进入“数据”页，两页初始都不接收。
- 两页共用连接栏的端口、波特率、串口参数和“收发文本编码”，发送区也共用；但同一时刻只有一个页面可以接收串口数据。
- 点击波形页的“开始接收”后，波形页成为唯一接收消费者，页面切换被禁用，“开始接收”同时变为“停止接收”。
- 必须先点击“停止接收”（会关闭物理串口）才能切换到其他页面。停止后切到另一页时，那一页保持停止状态，不会自动打开串口或开始接收；切页不会清除任何一页的历史。
- 数据页和波形页的接收历史、分帧器未完成尾部、解析状态和清空操作相互独立。数据页选择“原始字节”不影响波形页，波形页的帧也不会进入数据页历史。
- 页面清空只作用于当前页；日志是两页共用的应用级记录，任何页面清空都不会删除日志。
- 波形页的工具栏按钮包括“开始接收/停止接收”“清空波形”“日志目录”“跟随最新/回到最新”“自动缩放”和“X+”“X-”“Y+”“Y-”；页面内还有诊断、日志错误和历史淘汰提示，以及数据显示区、波形图和右侧通道栏。

### 7.2 十进制数值协议

波形页始终按连续字节 `0D 0A`（`\r\n`）识别帧结束，严格边界规则与数据页分帧模式一致：跨串口读取块、一次读取中的多帧、单独 `\r`、单独 `\n` 和 `\r\r\n` 的处理都相同。

完整载荷必须满足：

```text
[+-]?(?:[0-9]+(?:\.[0-9]*)?|\.[0-9]+)(,[+-]?(?:[0-9]+(?:\.[0-9]*)?|\.[0-9]+)){0,7}\r\n
```

- 1～8 个字段，用半角逗号 `,` 分隔。
- 每个字段是有符号十进制数值，数值范围为 `-2147483648..2147483647`；兼容整数、可选正负号、前导零，也接受 `0.96`、`.5` 和 `1.` 形式。
- 不接受空格、TAB、空字段、尾逗号、指数表示、`NaN`、`Inf`、HEX、非 ASCII 数字或超过 8 个字段。

示例：

```text
12\r\n
12,34\r\n
-10,+20,0030\r\n
```

完整合法帧会在接收正文中按原始拼写显示，例如 `0.96,328.00`，并产生数值采样；相对时间只显示在图表 X 轴和悬停读值中。完整但不符合语法的帧（包括空帧 `\r\n`）仍显示原始载荷，正文外显示“解析失败”，不产生采样点，也不改变通道数量。未完成的帧不显示、不采样、不写日志；单个未完成载荷超过 1 MiB 后会被丢弃并在波形页显示非模态提示，识别到下一个 `\r\n` 后自动恢复分帧。

波形协议只用 `\r\n` 表示“这一帧结束”，没有帧头、长度、序号或校验字段。软件无法判断设备端一帧从哪个字节开始，只按结束符切分；也不会替对端做帧起点识别或错误纠正。

### 7.3 相对时间、日志与连接边界

- 每个完整帧在接收线程识别到 `\r\n` 边界时记录一次高分辨率单调时间；`T+… s` 等于该时间减去本次采集原点（首次成功开始接收时建立的 `T+0`）。
- `T+` 只表示主机识别到完整帧的时间，不代表 MCU 的采样时刻；协议中没有设备采样时间字段。
- 单调时间不受系统时钟校准和时区变化影响，适合排序和绘图。
- RX 日志继续使用“帧完成”时的主机本地墙上时间，格式和日期分文件规则与数据页相同：`[HH:mm:ss.SSS] RX <原始帧 HEX>`。合法帧和完整非法帧都写日志；未完成帧和超长丢弃帧不写日志。
- 日志写入首次失败仍按既有规则熔断并显示固定错误提示；日志失败不停止波形接收、解析、采样保留或绘图。

停止与恢复：

- 点击“停止接收”会关闭物理串口，丢弃该连接尚未消费的队列数据、未完成帧和旧读取线程可能延迟返回的数据；已显示的波形、帧记录、通道和采集原点保留。
- 再次“开始接收”会创建新的读取会话，并在读取前清理串口驱动中残留的待读输入。停止期间设备继续发送的数据不会被缓存，也不会在重开后作为旧数据补收。
- 停止期间经过的单调时间会体现在恢复后第一条新帧的 `T+` 中，但期间不产生采样点。
- 如果停止后更改过端口或任一串口参数，恢复时会在波形页接收正文之外显示当前连接参数的“连接边界”提示；已有波形和采集原点不变。
- 参数或端口变化不会清空历史；只有“清空波形/新建采集”会重置时间原点和历史（见 7.6）。

### 7.4 数据显示区、通道与三分钟窗口

- 数据显示区最多保留最近 180 秒内完成的完整帧记录（合法与非法都包括），按最新完成帧的 `T+` 推进淘汰。正文默认跟随最新；上翻查看旧记录后，新帧继续接收和显示但不会强制移动阅读位置，按钮变为“回到最新”，点击后恢复跟随。正文只显示原始载荷，不显示 `payload=""`、逐帧 `T+` 或“解析成功”。
- 波形原始采样点保留最近 180 秒内的全部值，按最新合法采样点的 `T+` 推进淘汰。绘图可以按当前视口简化，但不会删除、合并或降采样原始点；放大或改变视图后可按对应范围恢复原始细节。
- 停止接收后没有新帧时，两种历史都不会因为电脑时间继续流逝而淘汰；恢复并产生新数据后，再按新的 `T+` 推进窗口。
- 通道按当前采集会话见过的最大合法字段数动态建立，最多 `CH1`～`CH8`，字段顺序就是通道顺序。更宽的合法帧只会增加通道；短帧、非法帧和历史淘汰都不会减少通道数。
- 短帧缺少的后续字段在该帧时间形成断点缺口，曲线断开显示，不沿用、复制或插值旧值。
- 右侧通道栏显示每个已发现通道的名称、显示开关和最新有效值。关闭某通道只隐藏曲线，采集、原始点保留和最新值继续更新；重新打开后从保留的原始历史恢复绘制。所有显示通道共用同一条 Y 轴。

### 7.5 波形图操作

- `X+`/`X-` 按钮分别放大/缩小 X 轴；`Y+`/`Y-` 按钮分别放大/缩小 Y 轴。
- 鼠标滚轮默认以指针附近的图表坐标为中心缩放 X 轴；按住 `Ctrl` 滚动则缩放 Y 轴。
- 在图表中按住鼠标左键拖动可平移视图：默认同时平移 X/Y，按住 `Shift` 只平移 X，按住 `Ctrl` 只平移 Y。
- “自动缩放”一次性把 X 轴适配当前保留的采样时间范围，并只按当前可见 X 范围内已打开通道的有效原始值设置 Y 轴；常值数据也会得到可见范围。
- “回到最新”把时间视口移到最新保留数据并恢复实时跟随；它与“自动缩放”是不同操作，不会自动改变 Y 轴。
- 手动缩放或平移后，新数据继续接收、保存和写日志，但视口不会被强制拉回或自动缩放；只有点击“回到最新”才恢复跟随。
- 当 180 秒滚动淘汰越过当前视口左侧时，视口会夹紧到仍保留的范围，并显示非模态的“历史正在滚动淘汰”。
- 鼠标悬停靠近曲线时，显示最近真实原始采样点的 `T+… s` 以及该帧实际存在的通道和值；短帧缺失的通道不会显示虚构值。指针没有靠近有效原始采样点时提示会隐藏。
- Y 轴硬范围限制在有符号 32 位整数域内（`-2147483648..2147483647`）；X 轴不会超出当前仍保留的采样时间窗口。

### 7.6 清空波形/新建采集

点击“清空波形”是一次完整的“新建采集”，在接收会话内原子执行，同时清除：

- 波形原始采样历史与绘图数据；
- 数据显示区的完整帧记录和时间戳；
- 通道推断、通道开关和最新值；
- 协议解析错误、超长帧提示、历史淘汰提示和悬停读数；
- 图表缩放/平移和阅读位置（恢复为无数据的默认视图）；
- 清空时已进入队列但尚未处理的帧、旧读取线程延迟发布的数据，以及分帧器未完成尾部。

清空前进入旧队列的数据不会在清空后重新出现。接收进行中清空不会关闭串口、不会停止接收，清空后的下一条完整帧以新的 `T+0` 计时；停止状态下清空同样安全，下一次成功开始时建立新原点。清空不会删除或修改任何已经写入的 RX 日志，也不影响数据页。

### 7.7 资源不足与恢复

如果内存分配失败或继续保留/绘制数据已无法安全进行，波形页会：

- 停止波形接收并关闭物理串口；
- 保留关闭前已经提交的采样和帧记录；
- 显示非模态的资源错误提示；
- 解除页面切换锁定，恢复可操作状态。

此时“开始接收”不会重新打开串口，必须先点击“清空波形”执行一次显式新建采集；成功后可以重新开始接收。软件不会静默丢弃 180 秒窗口内的原始点来“撑过去”。

### 7.8 Windows 原生图表交互验收

滚轮缩放、拖动平移、悬停读值和 QtCharts 坐标映射依赖原生窗口事件。发布前应在 Windows 桌面环境（非 offscreen）执行下面的自动化命令或手工步骤：

```powershell
$env:QT_QPA_PLATFORM = "windows"
.venv\Scripts\python.exe -m pytest tests/test_oscilloscope_interactions.py -q
Remove-Item Env:QT_QPA_PLATFORM
```

手工检查（建议同时使用 1080 x 680 和最小 760 x 480 两种窗口尺寸，并在 100% 与 125% 显示缩放下各检查一次）：

1. 在波形页点击“开始接收”，然后让对端发送包含正负值和多通道的合法帧（如 `12\r\n`、`-10,+20\r\n`）。
2. 滚轮上滚/下滚，确认只缩放 X 轴，且缩放中心在指针附近的图表坐标。
3. 按住 `Ctrl` 滚动，确认只缩放 Y 轴；`Y+`/`Y-` 按钮同样只影响 Y 轴。
4. 按住鼠标左键拖动，确认 X/Y 同时平移；`Shift+拖动`只平移 X，`Ctrl+拖动`只平移 Y。
5. 点击“自动缩放”，确认 X 适配保留数据、Y 适配当前可见范围内已开启通道；点击“回到最新”，确认视口回到最新并恢复跟随。
6. 把指针停在曲线上，确认显示 `T+… s` 和该帧真实存在的通道值；指针移开后提示消失。
7. 点击“停止接收”，确认页面切换恢复可用；重新开始后确认停止期间的数据没有被补收。

## 8. 发送数据

### 8.1 发送文本

1. “发送”选择“文本”。
2. 在连接栏的“收发文本编码”中选择正确编码。
3. 在发送输入框中输入内容。
4. 点击“发送”，或输入完成后按回车。

例如，发送中文时：

- 设备使用 UTF-8：选择 `UTF-8`。
- 设备使用 GBK：选择 `GBK`。

### 8.2 发送 HEX

1. “发送”选择“HEX”。
2. 输入两位十六进制字节。
3. 点击“发送”。

空格和逗号都可以作为分隔符，也可以混合使用：

```text
48 65 6C 6C 6F
48,65,6C,6C,6F
48 65,6C 6C,6F
```

以上三种写法都会发送：

```text
Hello
```

以下输入会被拒绝并提示错误：

```text
GG 01
0x01
01 2
123
```

HEX 模式下不能使用 `0x` 前缀，每个字节必须正好是两位十六进制字符。

## 9. 虚拟串口联调

没有真实设备时，可以使用 com0com 创建一对虚拟串口。当前开发环境使用：

```text
COM17 <-> COM19
```

端口号由 Windows/com0com 分配，其他环境可能不同；`COM3 <-> COM4` 仅作为下载 com0com 前的示例。

### 9.1 创建端口

安装 com0com 后，以管理员身份打开 com0com 的命令行工具，创建端口对。当前环境对应的命令为：

```text
install PortName=COM17 PortName=COM19
```

不同 com0com 版本的命令行界面可能略有差异，以安装目录中的 `setupc.exe` 帮助为准。

### 9.2 使用派蒙助手连接 COM17

1. 启动派蒙助手。
2. 点击“刷新”。
3. 选择 `COM17`。
4. 设置 `115200 / 8 / N / 1`。
5. 点击“打开”。

### 9.3 使用 COM19 另一端测试

可以使用 pyserial 自带的终端工具连接 COM19：

```powershell
cd E:\projects_learning\zhufei_helps
.venv\Scripts\python.exe -m serial.tools.miniterm COM19 115200
```

从 COM19 输入文本并按回车，派蒙助手应收到对应数据（miniterm 的默认行结束符就是 `CRLF`，正好构成 `\r\n` 帧边界）。也可以从派蒙助手发送数据，观察 COM19 终端是否收到；注意派蒙助手**不会**把发送的数据回显到接收区。

要联调波形页，先在派蒙助手中切到“波形”页并点击“开始接收”，再从 COM19 发送十进制数值帧；波形页接收期间不能切回数据页，需先“停止接收”。十进制数值帧示例见 9.4。

若接收区没有任何显示，按下面顺序排查：

1. 确认接收解析为“按 `\r\n` 分帧”（默认）时对端确实发送了 `\r\n`；否则切到“原始字节”模式即可立即看到内容。
2. 确认派蒙助手打开的是 `COM17`，对端连接的是 `COM19`，且两端波特率一致。
3. 确认没有把派蒙助手自己的发送内容当作接收内容期待（软件不回环自身发送）。

### 9.4 精确发送测试字节

下面的命令从 COM19 发送以 `\r\n` 结束的 UTF-8 字符串：

```powershell
cd E:\projects_learning\zhufei_helps
.venv\Scripts\python.exe -c "import serial; s=serial.Serial('COM19',115200); s.write('你好'.encode('utf-8')+b'\r\n'); s.close()"
```

派蒙助手在 UTF-8 文本模式下应显示：

```text
[HH:mm:ss.SSS] 你好
```

HEX 模式下应显示：

```text
[HH:mm:ss.SSS] E4 BD A0 E5 A5 BD 0D 0A
```

同时在日志文件 `%LOCALAPPDATA%\PaimonAssistant\logs\YYYY-MM-DD.txt` 中新增一行：

```text
[HH:mm:ss.SSS] RX E4 BD A0 E5 A5 BD 0D 0A
```

去掉命令末尾的 `+b'\r\n'` 再发一次：分帧模式下接收区**没有反应**，日志也不新增；切到“原始字节”模式后才会立即显示。这是预期行为，不是故障。

在波形页联调十进制数值协议时，先把派蒙助手切到“波形”页并点击“开始接收”，再执行：

```powershell
cd E:\projects_learning\zhufei_helps
.venv\Scripts\python.exe -c "import serial; s=serial.Serial('COM19',115200); s.write(b'0.96,328.00\r\n'); s.close()"
```

波形页接收正文应原样显示 `0.96,328.00`，并在图中出现 CH1、CH2 两个点；日志新增 `[HH:mm:ss.SSS] RX 30 2E 39 36 2C 33 32 38 2E 30 30 0D 0A`。把内容换成 `abc\r\n` 时，波形页仍显示原始载荷，正文外显示“解析失败”，不产生波形点，但仍写入日志：

```text
[HH:mm:ss.SSS] RX 61 62 63 0D 0A
```

### 9.5 检查异常处理

可以用以下方式检查错误提示：

- 用另一个程序先打开 COM17，再在派蒙助手中尝试打开 COM17。
- 启动两个派蒙助手实例，让它们竞争同一个 COM 口。
- 设备或虚拟串口断开后继续发送数据。
- 保持派蒙助手连接 COM17，使 COM17 短暂消失后在一次轮询内恢复，确认不会误关闭；连续两次轮询仍消失时，确认自动关闭并提示“串口已拔出，连接已关闭”。
- 拔除未选中的端口，确认静默移除；拔除已选中但未连接的端口，确认选择留空且不会自动打开其他端口。
- 在 HEX 发送模式输入非法字符。

预期结果是出现明确提示，程序不崩溃，并且可以重新选择端口后再次打开。

## 11. 已知限制

- 波形页协议只用 `\r\n` 作为唯一帧结束边界，没有帧头、长度或序号，软件无法识别设备端一帧从哪个字节开始；`T+` 是主机识别完整帧的时间，不是 MCU 采样时刻。
- 波形原始采样与完整帧记录只在内存中保留最近 180 秒，停止接收不会淘汰但关闭程序即丢失，暂不持久化。
- “原始字节”模式属于数据页，不产生波形；波形页始终使用自己的 `\r\n` 分帧与十进制数值协议解析。
- 数据页与波形页共用日期日志和日志故障熔断；任一页面的清空操作都不会删除已写入的日志。
- 软件只按 `\r\n` 识别帧边界，不解析载荷内部的协议字段（帧头、长度、命令字、校验和、JSON、Modbus 等）。
- “按 `\r\n` 分帧”模式下，没有结束符的数据不会显示、也不会写日志，且不会回环显示本机发送的数据；调试未知协议或对端不发送 `\r\n` 时，请切到“原始字节”模式。
- “原始字节”模式不写 `RX` 日志，也不提供时间戳。
- 载荷内部如果出现 `\r\n`，会被当作一次帧结束，软件不提供载荷内转义机制。
- 单个未完成帧的载荷超过 1 MiB 时会被丢弃，不生成事件也不写入日志。
- 接收历史保存在内存中，长时间高流量运行会增加内存占用；可以定期点击“清空接收”。
- 日志由主线程同步写入；写入期间界面可能短暂停顿，但不影响串口读取、分帧和事件生成。
- 多个派蒙助手进程可以追加写入同一日期日志文件，软件不保证进程之间的全局顺序。
- 串口配置目前不会自动保存，下次启动需要重新选择。
- com0com 是外部测试工具，不是派蒙助手的运行时依赖。
